# 06 · 行业与薪资参考

## 铁律：数据必须现场检索

**禁止直接使用训练数据中的薪资数字。** 校招薪资每年调整，城市、公司梯队、岗位方向差异极大，凭记忆作答会给出误导性结论。

**执行流程**：

1. 用 `WebSearch` 检索，关键词组合建议：
   - `【岗位】 【城市】 校招 薪资 2026`
   - `【公司名】 校招 offer 年包`
   - `【岗位】 应届生 白菜价 SP`
   - `【岗位】 薪资 城市 生活成本 对比`
2. 交叉验证 ≥2 个来源；优先采信结构化的招聘公告与多来源一致的区间。
3. **输出时必须标注**：`数据来源 | 采集日期 | 样本范围 | 口径（月薪/年包/是否含股票）`。

## 可参考的信息渠道（检索时优先定向）

| 渠道 | 适用 | 注意 |
|---|---|---|
| 牛客网 Offer 比较 / 讨论区 | 校招 offer 实报 | 自报数据，偏高者多 |
| OfferShow / 看准网 | 分档薪资 | 样本偏互联网 |
| 脉脉 / 职场社区 | 社招与行业趋势 | 情绪化内容多，需过滤 |
| 公司校招官网 / 宣讲会公告 | 官方口径 | 通常只给区间或不给 |
| 招聘平台（BOSS/猎聘） | 岗位薪资区间 | 区间下沿更接近真实 |
| 国家统计局 / 城市人社局 | 平均工资、落户政策 | 用于生活成本测算 |

**自报数据偏差提示**：论坛样本存在幸存者偏差与虚报倾向，实际中位数通常低于社区热度最高的数字。给区间时取偏保守的中位区间。

### 数据可信度判断

检索到数据后，先过一遍这张表再决定是否采信：

| 检查项 | 可信 | 存疑 |
|---|---|---|
| 样本量 | 明确给出样本数（如「基于 200 份 offer 统计」） | 只说「很多人」「普遍如此」 |
| 时间 | 标注了年份与月份 | 无时间标注，或数据超过 1 年 |
| 口径 | 说明月薪 / 年包、是否含股票、税前税后 | 只说「薪资 30w」而不说口径 |
| 可追溯 | 有原始链接或统计方法说明 | 二手转述、截图无出处 |
| 分布形态 | 给出区间或分位数 | 只给一个数字（通常是最高值） |

**交叉验证要求**：至少 **2 个独立来源**指向相近区间，才可作为结论输出。
若来源之间差异超过 30%，说明数据不可靠 —— 应扩大检索范围，或明确告知用户「各来源分歧较大」，
并把分歧本身作为信息呈现，而不是取个平均值了事。

**反向验证**：给完区间后，用「城市生活成本」做一次反向检验 ——
如果算出的月度可支配余额为负或极低，说明该薪资档位与城市不匹配，需要复核数据或调整城市建议。

## 降级路径：无法检索时怎么办

若运行环境没有联网检索能力，**不得凭训练数据编造薪资数字**。改为输出以下三项：

1. **明确声明**：「我无法实时检索，以下为结构性框架与检索方法，具体数字需要你自行核实。」
2. **给出检索关键词清单**（可直接复制去搜）：
   - `【岗位】 【城市】 校招 薪资 2026`
   - `【公司名】 校招 offer 年包 白菜价 SP`
   - `【城市】 应届生 平均工资 房租 中位数`
3. **给出分析框架**，让用户填入自己查到的数字，由本技能完成分档判定、城市性价比测算与 offer 对比（可用 `scripts/offer_calc.py`）。

**绝不可以做的**：给出一组看起来合理但没有来源的具体薪资数字。这比不给数字危害更大 —— 用户会据此做职业决策。

## 三档口径定义

校招 offer 通常按三档划分，**必须先向用户解释分档依据，再给数字**：

| 档次 | 俗称 | 通常对应画像 | 相对基准 |
|---|---|---|---|
| 标准档 | 白菜价 | 满足岗位基本要求，常规实习/项目经历 | 1.0× |
| 优质档 | SP（Special Offer） | 大厂实习 + 竞赛获奖 + 项目亮点突出，面试表现优秀 | 1.1–1.4× |
| 顶级档 | SSP（Super Special Offer） | 顶会论文 / 高含金量竞赛奖牌 / 核心大厂实习 + 稀缺方向匹配 | 1.4–2.0× |

**适用说明**：分档幅度因岗位而异 —— 算法岗三档差距最大，测试/运维/前端相对扁平；国企与研究所通常不分档，按学历与职级定薪。

### ② 行业发展前景

从四个角度简要分析（每项 2–3 句，不写空话）：
- **需求端**：该岗位近 2–3 年招聘量的变化趋势，是扩张还是收缩
- **供给端**：相关专业毕业生规模、转入门槛
- **技术变量**：AI/自动化对该岗位的替代或增强效应（必须具体到任务层级，如「基础标注与调参正被自动化替代，但方案设计与业务理解仍是瓶颈」）
- **政策与地域**：行业监管、地方产业政策的影响

### ③ 晋升路径

给出双通道模型，并注明典型年限（区间，非承诺）：

```
技术通道：初级 → 中级 → 高级 → 资深/专家 → 架构/技术负责人
管理通道：工程师 → 组长 → 经理 → 总监
```

补充说明：
- 各层级**核心能力变化**（初级拼执行力 → 中级拼独立设计 → 高级拼方案取舍与影响范围）
- **晋升的关键变量**：是否有代表性项目、是否有跨团队影响力、上级是否有晋升名额
- **常见卡点**：3–5 年是第一次分流（技术深耕 vs 转管理）

### ④ 转行风险

客观列出，不制造焦虑：
- **岗位内转换**（如 CV → 多模态、算法 → 算法工程）风险低，技能可迁移
- **跨岗位转换**（算法 → 产品/后端）需补充能力清单与时间成本
- **行业转换**（互联网 → 国企/制造业）需评估薪资落差、工作节奏、技能折旧
- 明确标注：**哪些能力会折旧（具体框架版本），哪些不会（数学基础、工程思维、系统设计）**

## 输出规范

1. 先给结论与区间表，再给分析与说明。
2. 所有数字标注来源、日期、口径与样本范围。
3. 使用区间表达，避免「一定能拿到 X」这类断言。
4. 结尾声明：「薪资受个人背景、面试表现、当年 HC 影响较大，以上数据用于建立预期区间，不构成承诺。」
5. 主动询问是否需要基于此数据做 **Offer 对比**（联动能力 5）或 **谈薪话术**（联动能力 5）。
