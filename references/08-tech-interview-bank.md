# 08 · 技术面题库（计算机 / 算法 / 嵌入式方向）

> 与 `03-interview-simulation.md` 配合使用：本文件提供题目与考点，评分仍走 10 分制评分卡。

## 一、技术面的真实结构

多数技术岗面试按此链路推进，时间占比参考：

| 环节 | 占比 | 面试官在验证什么 |
|---|---|---|
| 自我介绍 | 5% | 表达结构 + 与岗位的关联度 |
| **项目深挖** | **40%** | 是不是你做的、有没有真正的技术判断 |
| 基础原理 | 30% | 知识体系是否有断层 |
| 手撕代码 | 20% | 编码基本功 + 沟通习惯 |
| 反问 | 5% | 主动性、对岗位的理解 |

**结论：项目深挖是权重最高的环节，也是最容易翻车的环节。** 优先准备这里。

## 二、项目深挖：三层追问链

面试官不会只问「你做了什么」，而会沿这条链追下去。**每个项目都要提前准备这三层答案**：

**第一层 · 事实**
- 项目背景是什么？解决什么问题？团队几个人，你负责哪部分？
- 具体用了什么技术栈？为什么用它？

**第二层 · 判断**
- 为什么选 A 方案而不是 B？（→ 必须准备**技术选型对比表**：候选方案 / 优缺点 / 选型理由）
- 这个方案有什么局限？在什么情况下会失效？
- 如果数据量/并发/精度要求提高 10 倍，你的方案还成立吗？
- 你踩过的最大坑是什么，怎么定位的？

**第三层 · 反思**
- 如果重做一次，你会怎么改？
- 这个项目里你最有技术含量的工作是什么？
- 你在这个项目里学到的最重要的一点是什么？

**准备方法**：为每个项目写一张「追问应对卡」：

```
项目：【名称】
一句话价值：【为谁解决了什么问题，结果如何】
我的角色：【独立/主导/参与 XX 模块】
核心技术决策 1：【选了 X 而非 Y，因为 Z；代价是 W】
核心技术决策 2：【…】
关键数据：【指标】从 X → Y，测法：【怎么测的】
已知局限：【诚实说明】
如果重做：【改进方向】
```

## 三、基础原理题库

### 数据结构与算法基础
- 数组/链表/栈/队列/哈希表的适用场景与复杂度
- 哈希冲突的解决方式；HashMap 扩容机制
- 红黑树 vs 平衡二叉树 vs B+ 树；为什么数据库索引用 B+ 树
- 排序算法稳定性、复杂度、适用场景；快排最坏情况与优化
- 图的遍历；拓扑排序；并查集
- 动态规划的状态定义与转移推导（重点：如何从暴力递归优化到 DP）

### 操作系统
- 进程 vs 线程 vs 协程；上下文切换开销
- 进程间通信方式及各自适用场景
- 死锁的四个必要条件与预防/避免/检测
- 虚拟内存、页表、缺页中断、页面置换算法
- 用户态/内核态切换；系统调用过程
- 零拷贝（sendfile / mmap）原理
- 内存分配：栈/堆、内存对齐、内存泄漏排查

### 计算机网络
- TCP 三次握手/四次挥手；为什么不是两次/三次
- TCP 可靠传输：滑动窗口、拥塞控制（慢启动/快恢复）
- TCP vs UDP 选型场景；QUIC 解决了什么
- HTTP/1.1 → 2 → 3 的演进与各自解决的问题
- HTTPS 握手流程；对称/非对称加密的分工；证书链
- 从输入 URL 到页面展示的完整过程
- DNS 解析流程；CDN 原理

### 数据库与工程
- 索引原理、最左前缀、索引失效场景
- 事务 ACID 与隔离级别；MVCC 实现
- 慢查询定位与优化流程
- 缓存一致性（Cache Aside / 延迟双删）；缓存穿透/击穿/雪崩
- 消息队列的作用、幂等与顺序性保障
- 分布式：CAP、一致性哈希、分布式锁实现

### 编程语言（按岗位选）
- Python：GIL、深浅拷贝、装饰器、生成器、内存管理
- C/C++：指针与引用、内存布局、虚函数表、智能指针、RAII、移动语义
- Java：JVM 内存模型、GC 算法与收集器、类加载机制、并发工具
- Kotlin/ArkTS（移动端）：协程原理、状态管理、渲染机制

### 嵌入式 / 底层（如适用）
- 中断与轮询的取舍；中断上下文的限制
- RTOS 任务调度；优先级反转与解决
- 内存对齐、大小端、volatile 的作用与误用
- 通信协议：I2C/SPI/UART 差异；CAN 总线仲裁
- 交叉编译与烧录流程；如何调试死机问题
- 低功耗设计手段

## 四、算法手撕题库

**分类准备，不求量求覆盖**（每类 5–10 题即可形成手感）：

| 类别 | 代表题 |
|---|---|
| 双指针 / 滑动窗口 | 最长无重复子串、三数之和、盛水最多容器 |
| 二分 | 旋转数组查找、寻找峰值、二分答案（如「最小化最大值」） |
| 链表 | 反转链表（含区间）、环形链表检测、合并 K 个有序链表 |
| 树 | 层序遍历、最近公共祖先、二叉树直径、路径和 |
| 回溯 | 全排列、子集、组合总和、N 皇后 |
| 动态规划 | 最长递增子序列、编辑距离、背包系列、股票系列 |
| 图 | 岛屿数量、拓扑排序、最短路径（Dijkstra） |
| 堆 / TopK | 数组中第 K 大、数据流中位数 |
| 位运算 | 只出现一次的数字、位计数 |
| 设计题 | LRU 缓存、限流器、Trie |

### 手撕评分点（面试官实际在看什么）

1. **先沟通再写**：复述题意 → 确认边界（空输入、重复元素、溢出）→ 说思路 → 问能否开始写。**上来就写是常见扣分项。**
2. **说清复杂度**：写完主动给时间和空间复杂度。
3. **代码质量**：命名可读、边界处理、无冗余分支。
4. **自测习惯**：写完后自己举 1–2 个用例走一遍（含边界用例）。
5. **卡住时的正确反应**：说出当前思路和卡点，请求提示 —— 比沉默硬撑好得多。

## 五、CV / 算法方向专用题库

### 基础
- 卷积的输出尺寸计算；感受野计算
- 1×1 卷积的作用；3×3 堆叠 vs 5×5 的感受野与参数量对比
- BatchNorm 的原理、训练/推理差异、为什么能加速收敛；BN vs LN vs GN 的适用场景
- 池化的作用；为什么现在很多网络用 stride 卷积替代池化
- 激活函数演进：Sigmoid 梯度消失 → ReLU → LeakyReLU/GELU
- 反向传播手推一个两层网络（高频）
- 过拟合的成因与对策（数据增强、正则、Dropout、早停）
- 优化器：SGD/Momentum/Adam/AdamW 差异

### 检测与分割
- 目标检测流程：Backbone → Neck → Head
- Two-stage（Faster R-CNN）vs One-stage（YOLO/RetinaNet）的取舍
- Anchor-based vs Anchor-free；正负样本分配策略
- 损失函数：Focal Loss、IoU/GIoU/DIoU/CIoU 的演进动机
- NMS 原理与改进（Soft-NMS）；mAP 的计算方式（含 IoU 阈值与 PR 曲线）
- 语义分割 vs 实例分割 vs 全景分割的区别
- U-Net 的 skip connection 为什么有效；FCN → DeepLab 的演进
- 分割中的类别不平衡处理；Dice Loss vs CE Loss
- **裂缝分割专项**（如相关）：细长目标的分割难点、边缘精度评价指标（BFScore/边界 IoU）、形态学后处理的作用

### 训练与工程
- 数据不平衡的完整处理链路（采样/加权/损失/后处理）
- 数据增强策略（几何/色彩/MixUp/CutMix/Mosaic）及其适用边界
- 迁移学习与微调策略（冻结层选择、学习率设置）
- 学习率调度：warmup、cosine、step 的取舍
- 模型压缩：剪枝、量化（PTQ vs QAT）、知识蒸馏
- 部署：ONNX 导出常见坑、TensorRT 优化手段、推理延迟瓶颈定位
- 如何定位「训练 loss 正常但验证指标差」的问题（→ 数据泄漏 / 分布不一致 / 评估代码 bug，按此顺序排查）

### 论文与前沿（加分项，视岗位深度）
- 讲一篇你读过的相关论文：动机、方法、实验、局限
- 你的综述/论文工作的核心贡献是什么（若适用）
- Transformer 在视觉中的应用（ViT/DeiT/Swin）；注意力机制的必要性
- 多模态/自监督学习的基本范式

## 六、答题框架速查

| 题型 | 框架 |
|---|---|
| 概念解释 | 定义 → 原理 → 优缺点 → 适用场景 → 一个实例 |
| 方案设计 | 需求拆解 → 基线方案 → 瓶颈分析 → 优化方案 → 评估指标 |
| 对比题 | 逐个说核心差异 → 各自代价 → 选型判据（不要只列优缺点） |
| 排查题 | 现象 → 假设 → 验证手段（二分/日志/最小复现）→ 结论 |
| 开放题 | 先明确约束和评价标准，再给方案；承认信息不足并说明会如何获取 |
| 不会的题 | 「这块我没有深入做过，我的理解是 X（基于 Y 原理推测），回去我会补上」 |

## 七、使用方式

1. 用户指定方向与岗位后，从本文件挑选 5 题组成一轮模拟（1 项目深挖 + 2 原理 + 1 手撕 + 1 反问）。
2. 手撕题需给出**完整代码 + 复杂度 + 边界用例**，并说明面试中应如何边写边沟通。
3. 项目深挖题必须结合用户简历中的真实项目定制追问链，不要用通用题。
4. 用户答不上来时，不要直接给答案 —— 先给提示（指向相关原理），引导其自行推导。
