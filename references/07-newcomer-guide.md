# 07 · 职场新人指南

> 本文件所有内容以**可执行清单**形式给出。输出时直接给用户勾选清单与话术模板，不讲道理。

---

## 一、入职准备清单

### 材料（入职前 3 天备齐）

- [ ] 身份证原件 + 复印件 2 份
- [ ] 学历/学位证、成绩单（应届生）、学生证（实习）
- [ ] 银行卡（多数公司指定银行，提前确认）
- [ ] 一寸/两寸证件照（电子版 + 纸质各若干）
- [ ] 体检报告（按公司要求的三甲医院套餐）
- [ ] 离职证明/实习证明（如有）
- [ ] 学校三方协议、报到证（校招应届必需）
- [ ] 前公司公积金/社保账号（如需转移）

### 入职前功课

- [ ] 确认报到时间、地点、对接人及联系方式
- [ ] 问清第一周的安排（是否有入职培训、需要自带设备否）
- [ ] 提前了解团队业务：公司主力产品、所在部门的职责边界、近期公开动态
- [ ] 准备好 1 分钟自我介绍（用于入职群/团队会）
- [ ] 准备 3 个向 mentor 请教的问题（显得有准备，而非空手）

### 第一天

- [ ] 主动加团队成员联系方式，记住直属上级与 mentor 的称呼
- [ ] 要一份团队文档/代码仓库/权限清单
- [ ] 记录环境配置步骤（自己踩的坑写下来，是新人最自然的第一个贡献）
- [ ] 明确一件事：**你的 mentor 是谁、有问题优先找谁**

## 二、试用期避坑指南

**核心认知**：试用期考核的底层标准不是「惊艳」，而是**可预期** —— 交给你的事能否按时、按质、无需反复追问地完成。

| 高频坑 | 后果 | 正确做法 |
|---|---|---|
| 不懂不问，自己猜着做 | 方向错了，返工成本极高 | 卡壳超过 **30 分钟** 就带着「我的方案 + 卡点」去问，不要空手问 |
| 闷头做完才汇报 | 中途偏离无人纠正 | 关键节点主动同步；不确定时先给一版粗稿确认方向 |
| 过度承诺 | 交付延期，信任受损 | 估时留 20–30% 缓冲；不确定时说「我确认后 X 小时内回复你」 |
| 只做不说 | 做了很多但没人知道 | 工作留痕（文档、提交记录、周报），成果要可见 |
| 藏问题 | 小问题拖成事故 | 风险早暴露；「坏消息要第一时间说」是职场铁律 |
| 越级汇报 | 直属上级被绕过，关系恶化 | 有异议先与直属上级沟通，跨级只在特殊情况下 |
| 卷形式不卷产出 | 加班但无产出，评价更差 | 优先做有明确交付物的事；低价值事务主动确认是否必须做 |
| 把「学习」当产出 | 三个月后仍无交付 | 试用期必须有一个能拿出手的完整交付 |

**转正自评模板**：

```
试用期工作总结

一、核心交付（3 项以内，每项：做了什么 → 结果量化 → 影响）
1. 【项目】我负责【范围】，完成【产出】，【指标】从 X 到 Y。

二、能力成长
【技能】从不会到能独立完成【具体任务】

三、不足与改进
【一个真实不足】→ 已采取【具体措施】

四、下一阶段计划（与团队目标对齐）
```

## 三、周报 / 日报写法

**唯一原则：写结论与决策，不写流水账。** 「今天开了会、看了代码」是无效信息；「确认了 A 方案可行，B 方案因 X 放弃」才是。

### 周报模板

```
【本周进展】（对应目标，不是对应动作）
1. 【任务名】进度 100%｜产出：【可点击的交付物】
2. 【任务名】进度 70%｜当前卡在【具体问题】

【数据/结果】
- 【指标】本周从 X 变为 Y

【问题与风险】（必写，没风险就写「无」）
- 【问题】影响【范围】，我的方案是【X】，需要【谁】支持

【下周计划】
1. 【任务】目标产出【X】，预计【时间】
2. 优先级排序：P0 / P1

【需要的支持】
- 【具体请求】，希望【谁】在【何时】前给到
```

### 日报模板（三行制）

```
今日完成：【1–3 条，带产出】
遇到问题：【或写「无」】
明日计划：【1–3 条，带优先级】
```

**要点**：
- 数字 > 形容词。「优化了性能」→「接口 P99 从 620ms 降到 90ms」。
- 「需要的支持」栏是新人最容易被忽视的高价值栏位，主动提资源需求是专业表现。
- 风险要写，但必须**同时给方案**，不要只抛问题。

## 四、向上沟通技巧

**核心方法：结论先行（金字塔原理）。** 上级时间稀缺，先给结论，再给理由，最后给细节。

### 场景 1 · 汇报进度

```
【结论】X 项目能按期交付 / 需要延期 2 天
【依据】已完成 A、B，C 因【原因】比预期多花 2 天
【方案】建议【选项 1】或【选项 2】，我倾向【X】，因为【理由】
【需要】请您确认【具体决策点】
```

### 场景 2 · 暴露风险（越早越好）

```
【风险】X 可能导致【具体后果】，预计【何时】发生
【影响面】影响【范围/人数/进度】
【已做】我已【采取的措施】
【需要】请协调【谁】做【什么】
```

### 场景 3 · 请求资源 / 拒绝不合理需求

```
请求资源：
【目标】要完成 X，需要 Y 资源（人/时间/权限）
【收益】达成后【量化价值】
【替代】若无法提供，我建议降级为【方案 B】

拒绝 / 排期：
【现状】我手上 P0 是 A 和 B，本周可支配时间约 X 小时
【冲突】新增的 C 预计需要 Y 小时，会导致【A 或 B 延期】
【建议】请帮忙确认优先级：我按【顺序】推进，是否可以？
```

### 三条铁律

1. **不要只带问题去，要带方案去**（至少给 2 个选项并说明倾向）。
2. **坏消息第一时间说**，延迟汇报的风险远大于问题本身。
3. **书面留痕**：重要决策、口头确认的结论，会后用一句话 IM/邮件复述确认。

## 五、跨部门协作方法

### 启动阶段

- [ ] 明确**单一对接人**（避免多头沟通、责任模糊）
- [ ] 写清**输入 / 输出**：我需要你提供什么、我交付什么、格式与时间
- [ ] 确认**双方优先级**：你的需求在对方那里排第几？如果靠后，提前拉上级对齐

### 推进阶段

- [ ] **所有结论留痕**：IM 或邮件确认，口头共识不算数
- [ ] **设检查点**：不要等到 deadline 才看结果，中途设 1–2 个同步点
- [ ] **换位表述**：把「我需要你做 X」改成「为了达成【共同目标】，需要 X 支持，这样你也能【对方收益】」
- [ ] **卡住时升级**：对接人推不动 → 找对方上级或自己的上级对齐，但要**先告知对接人**，不要背后越级

### 冲突处理

| 冲突类型 | 处理方式 |
|---|---|
| 优先级冲突 | 拉双方上级对齐，用「共同目标」拆解，而非争论谁的活更重要 |
| 标准/口径冲突 | 回到原始需求文档或数据，用事实而非立场争论 |
| 责任边界冲突 | 明确写入文档并双方确认，避免下次再吵 |
| 人的情绪冲突 | 私下沟通，就事论事，不在群里争对错 |

## 输出要求

- 用户问「入职要准备什么」→ 直接给勾选清单，不写解释。
- 用户问「周报怎么写」→ 先给模板，再给一个**基于用户真实工作的示例周报**（需先追问用户岗位与本周工作）。
- 用户问「怎么跟领导沟通」→ 先问清具体场景（汇报/请求/拒绝/冲突），再给对应话术。
- 结尾主动询问：「需要我帮你把本周工作整理成一份周报吗？」
