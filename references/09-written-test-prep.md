# 09 · 笔试准备

## 一、先建立正确认知

**笔试是标准化筛选，不是能力评估。** 它的目的是用最低成本把候选人从几千人筛到几百人。
所以策略是「**拿到过线分**」，不是「做到最好」—— 在一道难题上耗 40 分钟导致其他题没时间，
是笔试最常见的死法。

**笔试是硬门槛。** 多数公司按分数划线，不过线简历再漂亮也没用。技术岗笔试通常在网申后 1–2 周内触发。

## 二、题型拆解（技术岗）

| 题型 | 占比 | 考察内容 | 备注 |
|---|---|---|---|
| 编程题 | 40–60% | 算法与数据结构 | 通常 2–4 题，分 ACM 模式与核心代码模式 |
| 选择题 | 20–40% | 计算机基础、语言细节、数学 | 408 + 概率统计 + 机器学习 |
| 专业题 | 视岗位 | 岗位相关理论 | 算法岗必有，测开/后端较少 |
| 简答 / 场景题 | 10–20% | 工程思维与表达 | 如「设计一个 XX 系统」 |

## 三、编程题最大的坑：平台模式差异

**很多人算法会做，却挂在输入输出解析上。** 这是笔试与刷题最大的差异，务必提前练。

| 模式 | 典型平台 | 你要写什么 | 主要风险 |
|---|---|---|---|
| **ACM 模式** | 牛客、赛码、各公司自建平台 | 完整程序，**自己解析输入、输出结果** | 输入格式读错，导致全部用例失败 |
| 核心代码模式 | LeetCode | 只写函数体 | 基本无输入输出风险 |

**ACM 模式必须提前练的四件事**：

1. **多组测试用例**：常见形式是「第一行是 T，接下来 T 组数据」，也可能是「读到 EOF 为止」
2. **不定长输入**：一行若干个数字，用 `split()` 切分
3. **输出格式**：是否要求行末空格、是否需要每组结果间空行、浮点数保留几位
4. **性能**：ACM 模式的数据规模通常更大，O(n²) 可能超时

Python 读入模板（笔试前务必手敲一遍）：

```python
import sys

# 单行多值
a, b = map(int, input().split())

# 多组用例：第一行是组数 T
T = int(input())
for _ in range(T):
    n = int(input())
    arr = list(map(int, input().split()))

# 读到 EOF（组数未知）
for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    nums = list(map(int, line.split()))
```

> **执行要求**：用户准备笔试时，**必须提醒先用目标平台的真题做一次完整模拟**，
> 而不是只刷 LeetCode。这是投入产出比最高的一次提醒。

## 四、备考路径（按剩余时间倒推）

| 剩余时间 | 策略 | 具体动作 |
|---|---|---|
| 4 周以上 | 系统刷题 | 按专题刷，每类 10–15 题，覆盖双指针/二分/DP/树/图/回溯 |
| 2 周 | 高频题 + 专项 | 只刷高频题型；补机器学习/专业题专项 |
| 1 周 | 真题模拟 | 按目标公司真题限时模拟，练输入输出与时间分配 |
| 3 天 | 维持手感 | 每天 2 题 + 过一遍错题本，不学新东西 |

**时间分配建议（以 120 分钟、3 道编程题为例）**：
选择题 20 分钟 → 简单题 20 分钟 → 中等题 35 分钟 → 难题 35 分钟 → 检查 10 分钟。
**单题卡住超过 20 分钟就跳过**，先拿能拿的分。

## 五、选择题考点清单（技术岗通用）

- **数据结构与算法**：复杂度分析、树与图的性质、排序稳定性、哈希冲突
- **操作系统**：进程 vs 线程、内存管理、死锁条件、页面置换
- **计算机网络**：TCP/UDP、握手挥手、HTTP 版本演进、DNS
- **数据库**：索引原理、事务隔离级别、SQL 基础
- **概率统计**：贝叶斯、期望方差、常见分布、排列组合
- **机器学习**：过拟合与正则化、损失函数、评价指标、经典算法原理
- **语言细节**：Python 的 GIL/深浅拷贝/可变默认参数；C++ 的指针、内存布局、虚函数

## 六、算法岗专业题高频考点

| 考点 | 常见问法 |
|---|---|
| 偏差方差分解 | 高偏差/高方差分别怎么解决 |
| L1 vs L2 正则 | 为什么 L1 稀疏？几何解释是什么 |
| 数据泄漏 | 交叉验证时哪些操作会导致泄漏 |
| 评价指标选择 | 类别不平衡时为什么准确率不可用？该用什么 |
| 损失函数 | 交叉熵 vs MSE 的适用场景与梯度特性 |
| 手推推导 | 逻辑回归梯度、两层网络反向传播 |
| 经典模型 | 讲清一个模型的动机、结构、局限 |

## 七、策略与心态

- **不要在一场笔试上耗尽所有精力**：笔试密集期可能一周 3–5 场，按重要性分配。
- **多场冲突时**优先意向度高的；次优选择可考虑放弃或裸考。
- **笔试挂了要立刻查冷冻期政策**（见 `10-application-strategy.md`）—— 部分公司挂了要等数月才能再投。
- **部分公司允许「笔试未通过可再考一次」**，具体政策需现场核实，不要凭记忆断言。
- 笔试通过率本身不高是常态，**不要因单场结果否定自己**。

## 八、输出结构

当用户提出「帮我准备笔试」时：

1. **确认三件事**：目标岗位与公司、笔试时间、当前刷题量
2. **给题型配比与考点清单**（按岗位定制，不要给通用清单了事）
3. **给按剩余时间倒推的备考计划**，落到「每天做什么」
4. **出 3–5 道模拟题**（编程题 + 选择题混合），逐题讲评
5. **必提醒**：先用目标平台真题模拟一次，练输入输出

> 编程题讲评时，参考 `08-tech-interview-bank.md` 第四节的「手撕评分点」。
