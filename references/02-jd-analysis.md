# 02 · JD 拆解

## 降级路径：用户没有提供 JD 时

**先尝试索取。** 明确告知用户：没有 JD 时关键词覆盖度只能按该岗位的通用画像估算，
准确度会明显下降，且无法判断该公司的具体侧重。索取时给一个明确的动作：
「从目标公司岗位页复制一份完整 JD（含职责 + 任职要求 + 加分项）即可」。

**若用户确实拿不到 JD**（岗位未公开、只有内推口头描述等），按以下方式处理：

1. **声明假设**：在输出开头写一句话说明所采用的画像，例如
   「本次未提供目标 JD，以下基于『自动驾驶感知岗』通用画像分析」。
2. **用方向细分替代 JD**：按 `references/01-resume-optimization.md` 第 7.4 节的细分方向表，
   确认方向后套用该方向的典型考察点作为关键词来源。
3. **标注不确定性**：覆盖度给区间而非精确值，并注明「有 JD 后需重算」。
4. **把 JD 列为待补项**：在报告末尾的「需要你补充的信息」里列出，说明补上后能带来什么改进。

**不得做的**：把通用画像伪装成真实 JD 分析，给出精确到个位数的覆盖度百分比。
这会让用户误以为数据可靠，据此做投递决策。

## 输入

用户粘贴的招聘 JD 原文（越完整越好，包含「岗位职责 + 任职要求 + 加分项」）。若只有岗位名称，先追问或按行业通用画像分析并声明假设。

## 输出五维度（固定顺序）

### ① 核心硬性要求

按四类抽取，做成表格，标注「是否满足 / 证据在哪」：

| 类别 | JD 原文表述 | 判定标准 | 用户现状 |
|---|---|---|---|
| 学历/院校/专业 | | 是否写「统招」「全日制」「硕士起」 | |
| 技能栈 | | 区分「必须」与「了解即可」 | |
| 经验/项目 | | 实习月数、项目类型、是否要求论文/竞赛 | |
| 证书/硬门槛 | | 四六级、CET、资格证、党员（国企） | |

**关键判断**：JD 里出现「熟悉/了解/掌握」的差异 —— 「熟悉」= 能独立用，「了解」= 听过概念，「精通」= 能讲原理和边界。据此判断自己的准备深度，不要一律按最高标准自我否决。

### ② 隐藏软要求（HR 视角反推）

招聘方不会写「我们会加班」，但措辞会暴露。按此表反推：

| JD 措辞 | 真实含义 | 面试可能怎么验证 |
|---|---|---|
| 能承受较大工作压力 / 抗压能力强 | 项目节奏快，加班是常态 | 「讲一次你在高压下的经历」 |
| 结果导向 / 强目标感 | KPI/OKR 压力明确，过程不重要 | 「目标没达成你怎么处理」 |
| 快速迭代 / 敏捷开发 | 需求变更频繁，返工多 | 「需求临时改动你怎么应对」 |
| 有 owner 意识 / 独当一面 | 人手紧，没人带，要自己找活 | 「没人指导时你怎么推进」 |
| 沟通能力强 / 跨团队协作 | 需要频繁对接非技术方 | 「讲一次和他人意见冲突的处理」 |
| 对技术有热情 / 自驱力 | 可能加班多或薪资一般，用成长性补偿 | 「最近在自学什么，为什么」 |
| 有较强的学习能力 | 上手期短，或技术栈冷门 | 「多久掌握一个陌生框架」 |
| 稳定性好 / 愿意长期发展 | 团队流失率高，或岗位枯燥 | 「你的职业规划」 |
| 有较强的文档能力 | 流程规范重，或需对接多人 | 「写过哪些技术文档」 |

### ③ 岗位薪资范围与城市性价比

**必须现场检索（WebSearch）** 该岗位 + 城市 + 应届/实习的公开薪资，再给区间。输出三项：

1. 月薪区间（分实习日薪 / 校招月薪两种口径）
2. **城市性价比测算**：`月薪 − 房租 − 通勤 − 基本生活 ≈ 可支配余额`，并对比 2–3 个候选城市
3. 附加价值：公积金比例（影响实际到手与购房）、落户政策、通勤时长、行业集聚度

> 数据必须标注**来源、采集日期、样本范围**；区间而非单点；并声明「个体差异大，仅供参考」。

### ④ 自身差距分析及短期补全建议

差距分三级，**不要把所有差距都说成致命问题**：

| 等级 | 定义 | 处理方式 |
|---|---|---|
| 🔴 硬门槛 | 学历/届别/专业/证书等无法短期改变 | 判断是否直接放弃该岗，或寻找放宽口径的同类岗 |
| 🟡 可补齐 | 技能/项目/经历可在 2–8 周内补 | 给出**具体补全路径**：学什么、用什么资料、产出什么可写进简历的东西 |
| ⚪ 可弱化 | JD 提到但非核心（如「了解 Docker 优先」） | 面试前临时了解概念即可，不必投入大量时间 |

补全建议必须落到**产出物**上（如「两周内用 YOLOv8 跑通一个目标检测 demo，产出：GitHub 仓库 + 一篇复现笔记」），而不是「建议加强学习」。

### ⑤ 面试高频考点预测

按「硬性要求 × 隐藏软要求」交叉生成 5–8 个预测题，每道题标注：
- 考察意图（面试官到底想验证什么）
- 回答要点（3 条以内）
- 常见踩坑

技术岗联动 `08-tech-interview-bank.md` 生成原理题/代码题/项目深挖题。

## 附加能力：JD 质量诊断

帮助用户避免浪费投递机会，识别以下信号：

| 信号 | 可能含义 | 建议 |
|---|---|---|
| 职责描述极宽（「负责整个平台」）+ 要求极低 | 岗位定位模糊，可能是杂活或外包 | 面试时追问团队规模与汇报线 |
| 长期挂岗、反复刷新 | 流动率高 / 挂岗收简历 / 内部没定 HC | 降低优先级，投递前先问 HR 岗位是否在招 |
| JD 含大量「其他领导交办事项」 | 职责边界不清，可能被塞非本职 | 面试追问典型一天的工作构成 |
| 薪资写「面议」且无区间 | 通常低于市场或看人下菜 | 投递前先问区间 |
| 要求 3 年以上却招应届 | 期望错配，入职后压力大 | 谨慎评估 |

## 输出格式要求

- 五个维度用二级标题分隔，每个维度先给**结论**再给依据。
- 结尾给一句总评：「该岗位匹配度 X/10，建议投递/谨慎投递/不建议，理由是 …」。
- 主动追问是否需要接着做**简历关键词覆盖度改写**（联动能力 1）。
